# Leaderboard run details

Implemented in the isolated worktree on branch `feat/leaderboard-run-details`.

Each newly completed personal best now saves and submits both energy figures and a snapshot of its turret layout:

- **Earned:** energy generated during that run.
- **Invested:** energy spent on the defense used for this run, recorded at run start. The starting turret is free; purchased turrets cost 20, 30, 40, etc. For example, three total turrets represent 50 invested energy. Unspent savings and refunds from past layouts are excluded.
- **Turret layout:** normalized turret coordinates and arena dimensions, captured before returning to preparation. Moving turrets, resetting the layout, retrying publication, or reopening the game preserves the completed record's snapshot.

The website shows invested energy first, followed by run earnings, beside survival time. This lets players compare survival against the progression supporting each defense. An expandable **Turret layout** diagram displays the saved defense pattern, with blue turret markers and an arena-center guide. It supports keyboard interaction and mobile screens. It is a diagram generated directly from run data; screenshot uploads and image storage are unnecessary. The game currently has one turret type, so positions describe the layout without additional weapon configuration fields.

Older scores and pending offers continue to work. Missing details are explicitly marked **Not recorded**, while actual zero energy remains zero. Equal or lower submissions preserve the existing best and its details. A better submission replaces the complete record, including clearing previous details when an old client submits it.

The earlier preview's available-energy balance is not defense investment. Existing `totalEnergy` values remain compatible with storage and submission but are not shown as investment. New game runs send `energyInvested` instead. Previously published test records may show investment as **Not recorded** until a new best is published from the updated game. Restart the running test game to load this change; the already-running instance retains the previous logic.

The publication prompt now tells the player that energy and turret positions will be public. Duration still determines rank. The server validates energy, arena dimensions, coordinates, turret count, and request size.

## Release status

Changes have not been pushed or deployed to production. The updated backend has been deployed to the project's development deployment, `notable-giraffe-170`, for manual testing. The website dev server uses that deployment at `http://localhost:3000`. The temporary game launcher at `/tmp/little-last-light-leaderboard-preview.gd` enables publication for v0.0.1 against development and uses the separate `user://leaderboard-preview-progress.json` test save. Normal game settings and regular progress are unchanged.

For production, deploy the updated Convex backend and website, then release the updated game. Existing records do not require a database backfill, and their original energy/layout cannot be reconstructed retrospectively.
